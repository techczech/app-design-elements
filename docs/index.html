App design elements

Every Mac app I build has the same sixteen elements. If you know how to use one of my apps, you already know how to use the next: the same keyboard shortcuts open the same things, the menus are laid out the same way, and Settings looks the same.

Each command in an app is defined once, in one list. The command palette, the menu bar, the cheat sheet of keyboard shortcuts and the list of actions an AI agent can ask the app to perform are all built from that list, so they always agree. If you change a shortcut in Settings, the menu bar and the cheat sheet show the new one.

An app differs from the others only where its subject requires it, and the difference is written down. Anything an app can do with your content, an AI agent can do too, using the same actions the buttons and menus use. An agent can also read and change settings, and each change it makes appears in the list of changes you see in Settings.

This site has one page per element, and the full Settings design to click through. The table below lists all sixteen elements in plain terms.

The 16 elements

#NameWhat it means for you
1List of all commandsEvery action has a name in plain words and, where it has one, a keyboard shortcut; the palette, menus, cheat sheet and shortcut settings are all built from this list.
2Command palette ⌘⇧PShows every command in the app with its current shortcut, and ⌘⇧, lets you change the shortcut of the highlighted command on the spot.
3Keyboard shortcuts every app keeps the same⌘⇧P opens the palette, ⌘K the actions for your selection, ⌘, Settings, ⌘/ the cheat sheet, ⌘F finds in the document and ⌘⇧F searches everything; ⌘⇧K and ⌘P are used the same way in apps that have a switcher or a preview panel, and a key stays unused in an app that lacks that feature.
4A key for every button, and keys you can changeWhatever you can click, you can also reach from the keyboard, and you can reassign any shortcut; your choice is the one that counts.
5Shortcut cheat sheet ⌘/Lists every shortcut as it is set now, including your own changes, and opens while you are typing.
6Mac menu barBuilt from the same list of commands, with the current shortcut beside each item, in the same order in every app: the app's own menu (with Settings…), Edit, View, the app's menus, Window and Help.
7Actions for what you have selected ⌘KLists what you can do to the current selection, where you are; it also serves as help for that place.
8Switcher ⌘⇧K and preview panel ⌘PIncluded only in apps where the work needs a quick way to jump between things or to look at one in detail.
9Find and search⌘F finds within the document you have open and ⌘⇧F searches across everything; every app has both unless a reason for leaving one out is written down.
10Settings windowOpens in its own window with ⌘, from the first release; you can search it, see which settings you have changed and reset each one, review a list of every change and who made it, rebind shortcuts, and see the version you are running. Account keys are stored encrypted.
11Your agent can use the appWhatever an app can do with your content, an AI agent can do through the same actions the interface uses, and it can read and change settings from the command line, with each change recorded in the same list you see.
12Getting startedA Get started button that removes itself once you have used it, an example project that teaches the commands one task at a time, and a section explaining how the app works.
13Help where you areAfter getting started, help comes from ⌘K, ⌘/ and the Help menu; no explanatory text stays on screen permanently.
14Layout and lookEach app looks like a Mac application, not a website: light by default with dark as an option, clearly separated panels, real icons, designed buttons, lists you can search and sort, and empty space on the left rather than the right.
15Empty, loading and error screensEvery screen has a designed look for being empty, loading, refused, in the middle of an operation, finished or in error; an error says in plain words what went wrong and what you can do next.
16Plain wordingText says what you do and what you get, in one spelling convention per app, with no internal jargon or ids on screen.
