| # | Name | What it means for you |
|---|---|---|
| 1 | List of all commands | Every action has a name in plain words and, where it has one, a keyboard shortcut; the palette, menus, cheat sheet and shortcut settings are all built from this list. |
| 2 | Command palette ⌘⇧P | Shows every command in the app with its current shortcut, and ⌘⇧, lets you change the shortcut of the highlighted command on the spot. |
| 3 | Keyboard shortcuts every app keeps the same | ⌘⇧P opens the palette, ⌘K the actions for your selection, ⌘, Settings, ⌘/ the cheat sheet, ⌘F finds in the document and ⌘⇧F searches everything; ⌘⇧K and ⌘P are used the same way in apps that have a switcher or a preview panel, and a key stays unused in an app that lacks that feature. |
| 4 | A key for every button, and keys you can change | Whatever you can click, you can also reach from the keyboard, and you can reassign any shortcut; your choice is the one that counts. |
| 5 | Shortcut cheat sheet ⌘/ | Lists every shortcut as it is set now, including your own changes, and opens while you are typing. |
| 6 | Mac menu bar | Built from the same list of commands, with the current shortcut beside each item, in the same order in every app: the app's own menu (with Settings…), Edit, View, the app's menus, Window and Help. |
| 7 | Actions for what you have selected ⌘K | Lists what you can do to the current selection, where you are; it also serves as help for that place. |
| 8 | Switcher ⌘⇧K and preview panel ⌘P | Included only in apps where the work needs a quick way to jump between things or to look at one in detail. |
| 9 | Find and search | ⌘F finds within the document you have open and ⌘⇧F searches across everything; every app has both unless a reason for leaving one out is written down. |
| 10 | Settings window | Opens in its own window with ⌘, from the first release; you can search it, see which settings you have changed and reset each one, review a list of every change and who made it, rebind shortcuts, and see the version you are running. Account keys are stored encrypted. |
| 11 | Your agent can use the app | Whatever an app can do with your content, an AI agent can do through the same actions the interface uses, and it can read and change settings from the command line, with each change recorded in the same list you see. |
| 12 | Getting started | A Get started button that removes itself once you have used it, an example project that teaches the commands one task at a time, and a section explaining how the app works. |
| 13 | Help where you are | After getting started, help comes from ⌘K, ⌘/ and the Help menu; no explanatory text stays on screen permanently. |
| 14 | Layout and look | Each app looks like a Mac application, not a website: light by default with dark as an option, clearly separated panels, real icons, designed buttons, lists you can search and sort, and empty space on the left rather than the right. |
| 15 | Empty, loading and error screens | Every screen has a designed look for being empty, loading, refused, in the middle of an operation, finished or in error; an error says in plain words what went wrong and what you can do next. |
| 16 | Plain wording | Text says what you do and what you get, in one spelling convention per app, with no internal jargon or ids on screen. |
